# コマンドヘルプと処理中表示

## 決定

- 実行用ヘルプは、TypeScriptコードではなく`content/help/<command>.txt`へ置く。静的コマンドでは任意とし、存在しない場合は返信本文を使う。
- `o.help`は`content/help/index.txt`、`o.<command> help`は対応するコマンド名のテキストを表示する。
- ヘルプファイルはBOM付きUTF-8のプレーンテキストとし、ユーザーがJSON記法やコードを触らず編集できるようにする。
- requirementsは仕様の正本、`content/help/`は利用者向け表示文とし、ヘルプ文で仕様を上書きしない。
- ヘルプ実行時にファイルを読み、ローカルではビルドなしで変更を反映できるようにする。
- ファイル取得失敗の詳細はログへ残し、Discordには簡潔なエラーだけを返す。
- sale、gatya、item、utの通常検索・originでは処理中表示を使用せず、処理完了後に結果またはエラーだけを送信する。
- `ut motion`だけは2026年9月12日の利用者要望により例外とする。低性能コンテナでの待機・生成状況を、一つの本文メッセージへの段階・フレーム割合の編集で示す。アニメーションは使用しない。
- motionの進行度は同じ段階では原則2秒以上空けて更新し、終了後は完了またはエラー文として残す。添付ファイルには引き続き本文を付けない。

## 理由

ヘルプをユーザーが簡単に追加・修正できる状態にし、表示文の変更をコード変更から切り離す。通常の外部データ取得では処理中表示を使わない。motion生成は待機列と長い処理があり進行度が有用なため、削除不要の単一メッセージに限定して例外とする。他コマンドへ広げる場合は要件を先に確定する。
