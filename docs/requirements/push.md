# 更新検知通知とpush

## 今回の範囲

イベント監視側からの検知通知を受け取り、Botが最優先で設定済みチャンネルへ通知する。skdの取得・解析・追加内容の表示は[skd通知要件](skd-notifications.md)に従う。

## 運用条件

BotはNorthflankの無料枠で動かす。利用者PCの常駐運用や、永続ローカルディスクを前提にしない。無料DB/Addon枠の空き状況は未確認。

2026-09-06決定: 専用private GitHubリポジトリを正本とする。メモリと一時ファイルはキャッシュであり、これらだけにある情報を保存完了と扱わない。

決定理由と詳細設計は[Northflank保存方針・設計](../decisions/northflank-storage.md)に記載する。通知前に送信予定を保存し、送信結果が不明なら自動再投稿せず保留する。保持期間は未決定。管理者と保存の要件は[保存要件](storage.md)を参照。

## 通知先

- `o.push skd`: 実行したチャンネルにgatya・sale・itemの通知を登録する。
- `o.push ad`: adcontrol.jsonに対応するadの通知を登録する。
- `o.push notice`: placementのevent.jsonに対応するpopup_noticeの通知を登録する。
- 末尾に`off`を付けて、そのチャンネルの該当通知を解除する。
- 複数チャンネルを登録できる。同じ設定の再登録で重複させない。
- 操作対象者は固定Bot管理者・健康維持メンテナー。今回は権限コマンドと判定の接続を保留する。

## 表示

スケジュールとad・popup_noticeの通知を分ける。スケジュールは最初に次を投稿する。

```text
**スケジュール更新を検知**
検知時刻: 2026/09/06(日) 00:00:00
```

更新された種類を受信したら、同じ投稿を編集して`種類: gatya,sale`のように追記する。時刻はJST、元の検知時刻を保持する。

adは`adの更新を検知`、noticeは`popup_noticeの更新を検知`を先頭行にし、同じ形式の検知時刻を表示する。
