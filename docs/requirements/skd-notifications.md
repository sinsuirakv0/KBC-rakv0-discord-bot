# skd更新通知

2026-09-10のユーザー指定。ad・noticeの機能追加は今回の対象外。

- 通知先は旧スケジュール通知のトークを引き継ぐ。登録先IDは専用privateデータrepoに保存する。
- ワークフローが重なっても同じ更新を二重通知しない。
- 最初に検知通知を送り、更新種類は同じ投稿へ追記する。
- Botが更新対象のTSVを取得し、KBC-rakv0-eventのパーサーで解析する。
- 更新前のrawにある種類別の最新TSVと、今回のTSVを同じパーサーで解析し、追加されたイベントをgatya、sale、item、missionに分け、この順で送る。
- 各種類は独立したコードブロックにし、各最大5件。残りは「その他〇件」と表示する。
- 開催日時・バージョンだけ差し替わった予定は追加分から外し、追加分の後の「変更」コードブロックへ4種類まとめて表示する。種類名と変更前→変更後を示し、合計最大5件、残りは「その他〇件」と表示する。元の予定が残ったまま別の予定が増えた場合は追加分とする。
- 一覧の名前・日時・ガチャフラグ・開催期間・数量はo.gatya / o.sale / o.itemに準じる。missionはsaleのミッション分類・名前解決を使う。
- missionは原文の改行と`<br>`をコードブロック内の改行として表示する。複数行でも1ミッションを1件と数える。
- 追加がない種類のコードブロックは省く。追加がある種類はgatya、sale、item、missionの順を保ち、変更がない場合は「変更」欄も省く。終了済み・常設の除外は既存一覧に合わせる。301・302はitemに表示する。
- 追加分と変更欄の送信完了後、旧スケジュール通知と同じKBC履歴リンクを送って終了する。
- 送信結果が不明な投稿を自動で再投稿しない方針を、種類別の追加通知にも適用する。

権限コマンドは引き続き別作業。[保存要件](storage.md)に従う。
